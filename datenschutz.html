2. Zweck und Geltungsbereich

Diese Datenschutzerklärung gilt für die LIE Scorecard unter app.lochihnein.de. Die Anwendung ist für eine private Golf- und Freundesgruppe bestimmt und nicht für Kinder oder Jugendliche vorgesehen.

Verarbeitet werden nur Daten, die für Anmeldung, Gruppenorganisation, Spieltage, Score-Erfassung, Handicap-/Statistikfunktionen und die optional angeforderte Wetteranzeige erforderlich sind.

3. Welche Daten werden verarbeitet?

  • Spielerstammdaten wie Name, Spitzname, E-Mail-Adresse, Rolle und Golf-/LIE-Handicap.
  • Spieldaten wie Spieltage, Flights, Scores und zugehörige Ergebnisse.
  • Technische Authentifizierungsdaten von Firebase, insbesondere die für die Sitzung verwendete interne Spielerkennung und Authentifizierungstokens.
  • Eine lokal im Browser gespeicherte Spielerkennung, damit die Sitzung beim nächsten Aufruf wiedererkannt werden kann.
  • Bei Nutzung der Wetterfunktion: die vom Browser freigegebenen Standortkoordinaten. Diese werden zur Abfrage der Wetterdaten an Open-Meteo übermittelt und von der Anwendung nicht als dauerhafter Standortverlauf in Firestore gespeichert.
  • Bei Anforderung eines Einmal-Codes: E-Mail-Adresse und ein zeitlich begrenzter temporärer Anmeldecode.

4. Anmeldung mit Name und PIN

Die Bedienung bleibt bewusst einfach: Spieler auswählen, PIN eingeben, fertig. Die PIN wird nicht mehr vom Browser aus Firestore gelesen oder dort im Klartext geprüft. Die Prüfung erfolgt serverseitig über Firebase Cloud Functions. PINs werden als kryptografisch abgeleitete Hashwerte gespeichert.

Nach erfolgreicher serverseitiger PIN-Prüfung erzeugt Firebase ein benutzerdefiniertes Anmeldetoken (Custom Token). Die App verwendet dieses Token für die Firebase-Authentifizierung; anschließend erhält die Sitzung ein Authentifizierungsmerkmal, das den Zugriff auf die geschützten Firestore-Daten ermöglicht. Nicht angemeldete Sitzungen können keine geschützten Spiel- oder Profildaten aus Firestore lesen.

5. Firebase / Google

Die Anwendung verwendet Firebase-Dienste von Google, insbesondere Firebase Authentication, Cloud Firestore und Cloud Functions. Diese Dienste verarbeiten die für Anmeldung und Datenhaltung erforderlichen Informationen. Die Firebase-Web-SDKs werden von gstatic.com geladen.

Die Speicherung der Spiel- und Profildaten erfolgt in der mit der Anwendung verbundenen Firebase-Projektumgebung. Für die genaue technische Speicherung, Protokollierung und mögliche internationale Datenübermittlungen gelten ergänzend die Informationen und Vertragsbedingungen des jeweiligen Dienstes.

6. Einmal-Code per E-Mail / Google Apps Script

Über „PIN vergessen / Code per Mail anfordern“ kann ein temporärer Code angefordert werden. Die Anwendung erzeugt den Code serverseitig, speichert nur dessen Hash und übermittelt die für den Versand erforderlichen Angaben an das bestehende Google-Apps-Script-Mailbackend. Dieses liest die hinterlegte E-Mail-Adresse aus der administrativen Google-Tabelle und versendet den Code.

Die E-Mail-Adresse wird ausschließlich für diesen Zweck und für die in der Gruppe vorgesehene Kommunikation verwendet.

7. Wetter und Standort

Die Wetteransicht kann den Browser um Zugriff auf den aktuellen Standort bitten. Dies geschieht nur nach Freigabe durch den Nutzer. Die Koordinaten werden an Open-Meteo übermittelt, damit passende Wetterdaten abgefragt werden können. Die Anwendung speichert keinen dauerhaften Bewegungs- oder Standortverlauf.

Wenn der Standortzugriff verweigert wird, kann die Wetterfunktion je nach App-Version mit einem voreingestellten Ersatzstandort arbeiten.

8. Externe Bibliotheken und CDNs

Die Anwendung lädt technische Bibliotheken von Drittanbietern, unter anderem Tailwind CSS über jsDelivr, Font Awesome über cdnjs und Firebase über gstatic.com. Beim Abruf dieser Ressourcen kann die IP-Adresse des Geräts technisch an den jeweiligen Anbieter übermittelt werden.

Die Anwendung verwendet nach dem aktuellen Projektstand keine eigene Reichweitenmessung, kein Werbetracking und keine Profilbildung zu Werbezwecken.

9. Cookies und lokale Speicherung

Die Anwendung setzt nach dem aktuellen Projektstand keine eigenen Tracking-Cookies. Für die Sitzungsfunktion verwendet Firebase Authentication technische Browser-Speichermechanismen. Zusätzlich wird die interne Spielerkennung lie_scorecard_user_id im lokalen Speicher des Browsers abgelegt.
